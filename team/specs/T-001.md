# T-001 Stream the polished output into the right pane as it is generated
Status: specced
Size: small (target ≤ 200 changed lines including all tests; no new dependencies)

## Problem
The demo (MISSION.md "Current goal") is: hold Space, ramble ~20 s, release, and
see a polished Markdown note with visible, honest latency numbers. Today the
right pane shows a static "Polishing…" placeholder until the LLM Gateway has
returned the *whole* completion (`POST /api/polish` in `app.py` waits for the
full JSON response; `stop()` in `static/index.html` renders it in one go). For a
~20 s ramble the viewer watches a blank pane for the entire LLM round trip.

HYPOTHESIS: showing the first polished words as soon as the model emits them
makes the app feel substantially faster on camera, even though total time is
unchanged. Evidence: none (MISSION.md "Evidence we have: None yet"); this is the
owner's #1 priority on the 2026-09-27 improvement list. Cheapest test: the owner
records one take before and one after and judges the footage.

Feasibility: AssemblyAI documents that the LLM Gateway supports `stream: true`
on `/v1/chat/completions`, returning an OpenAI-compatible Server-Sent Events
stream (source: assemblyai.com/blog/stream-llm-responses-voice-pipeline-tool-calling-structured-outputs-real-time-actions,
assemblyai.com/docs/llm-gateway/quickstart). Not verified live: there is no API
key in the agent environment.

## Outcome
After releasing Space, the user watches the polished Markdown appear
progressively in the right pane instead of waiting for the full response, with
honest latency badges for "first polished text" and "done".

## Acceptance criteria
All criteria must be verifiable without an AssemblyAI key: backend criteria via
`httpx.MockTransport` in pytest (as in `tests/test_app.py`); browser criteria via
the Playwright harness in `scripts/e2e_check.py` (fake mic, fake socket, and a
faked polish response that delivers chunks with delays) plus a screenshot.

Backend (pytest, mocked upstream):
- [ ] Given a non-empty transcript, when the browser requests a polish, then the request the server sends to the LLM Gateway asks for a streamed completion (`"stream": true`) and still contains the unchanged system prompt, the transcript as the user message, the configured model, and the server-side API key.
- [ ] Given the mocked gateway streams an SSE response whose deltas are "**Launch", " update**", "\n\n- Friday" followed by `[DONE]`, when the polish response body is read to the end, then the concatenated text the browser receives is exactly "**Launch update**\n\n- Friday" (no SSE framing, no `[DONE]`, no JSON).
- [ ] Given the mocked gateway returns a normal non-streamed JSON completion (fallback: the gateway ignored `stream`), when a polish is requested, then the browser receives the full completion text, with no error.
- [ ] Given the gateway responds with a non-200 status (e.g. 401 "Invalid API key") before any text, when a polish is requested, then the server responds 502 with a detail containing the status code and upstream message (same behaviour as today).
- [ ] Given an empty or whitespace-only transcript, when a polish is requested, then the server responds 400 and makes no upstream call (unchanged).
- [ ] Given `ASSEMBLYAI_API_KEY` is unset, when a polish is requested, then the server responds 500 with a message naming `ASSEMBLYAI_API_KEY` and makes no upstream call.

Browser (Playwright harness + screenshot):
- [ ] Given a dictation has finished and the polish response delivers its first chunk, then that chunk's text is visible in the Polished pane while later chunks have not yet been delivered (i.e. rendering is progressive, not all-at-once).
- [ ] Given the stream has completed, then the Polished pane shows the full Markdown rendered (bold title, list items), identical to how the same text renders today.
- [ ] Given the streamed text contains `<script>alert(1)</script>`, then no `<script>` element appears in the Polished pane at any point during or after streaming.
- [ ] Given streaming is in progress, then the Copy button is disabled; given the stream has completed, then Copy is enabled and the clipboard (auto-copy) holds the full Markdown, not a partial.
- [ ] Given the stream has completed, then the badges show browser-measured times in ms: a "first polished text" time (release → first polished text visible) and the existing "AI polish" (polish request → last chunk) and "Stop → polished" (release → last chunk). No badge shows a value that was not measured on this take.
- [ ] Given the polish request fails (502 before streaming), then the red error banner shows the server's detail and the status badge returns to "idle", and a new dictation can be started.
- [ ] Given the stream is cut off mid-response (connection error after some text), then the error banner is shown, the status badge returns to "idle", Copy stays disabled, and a new dictation can be started.
- [ ] Given two dictations in a row, then the second take's Polished pane contains only the second take's text (nothing from the first take is appended).
- [ ] All pre-existing checks in `scripts/e2e_check.py` still pass, and `./scripts/check.sh` exits 0.

## Out of scope
- Any change to the system prompt, model choice, or what the LLM is asked to do.
- Streaming or changing the raw (left) pane — it is already live.
- A cancel/stop-polishing button, retries, or automatic fallback to a second model.
- Improving the Markdown renderer (tables, code blocks, links).
- Adding Playwright to CI or to `requirements.txt` (dependency + `.github/` change; owner decision, see questions.md).
- Keeping a separate non-streaming polish mode in the UI.

**Badge (new), inserted between `bFinal` and `bLlm`:**
`<div class="badge" id="bFirst">First polished text: <b>–</b></div>`
Badge order: Status · Final transcript · First polished text · AI polish · Stop → polished. Values are `"<n> ms"` (integer, same format as today), green (`good`) when set.
- `First polished text` = release (`stoppedAt`) → first non-empty chunk rendered.
- `AI polish` = polish `fetch` start → last chunk (browser-measured; no longer the server's `llm_ms`).
- `Stop → polished` = release → last chunk.

**Behaviour by state (exact):**
| State | Status badge | Polished pane | Copy | Polish badges |
|---|---|---|---|---|
| Release (before polish) | `finalizing…` (unchanged) | unchanged | disabled, label `Copy` | reset all three to `–` at release; clear `polishedMarkdown` |
| Waiting for first chunk | `polishing…` | placeholder `Polishing…` (unchanged copy) | disabled | `–` |
| Streaming | `polishing…` | rendered accumulated Markdown | disabled | First set; others `–` |
| Done | `idle` | full Markdown | enabled, auto-copy → `Copied ✓` / `Click to copy` (unchanged) | all three set |
| Fallback (JSON, not streamed) | same as Done | full note appears at once | as Done | all three set (First ≈ Stop → polished; that's honest) |
| Error before text (e.g. 502) | `idle` | empty placeholder `Clean, formatted text appears here when you stop talking.` | disabled | all `–` |
| Cut off mid-stream | `idle` | partial text kept, `#polished` gets class `cut` (dimmed) | disabled | First keeps its value; AI polish and Stop → polished `–` |

- New CSS (one line): `#polished.cut { opacity:.6; }` (resulting text ~#9da3ad on #1e293b ≈ 5.7:1, passes AA). Remove the class when the next polish starts.
- Do not special-case half-finished Markdown (e.g. a chunk ending in `**Launch`): the literal `**` shows for one chunk and is fixed by the next. Renderer changes are out of scope.
- No auto-scroll of the pane during streaming; the card grows as today.

**Copy (every user-visible string):**
- Badge label: `First polished text:` (empty value `–`).
- Waiting placeholder: `Polishing…` (unchanged).
- Empty placeholder after an error-before-text: `Clean, formatted text appears here when you stop talking.` (existing string).
- Error before text: the server's `detail`, verbatim (unchanged; e.g. `LLM Gateway request failed (401): {"error":"Invalid API key"}`). Fallback if no detail: `Polish failed.` (unchanged).
- Cut off mid-stream: `Polishing was cut off before it finished. The text below is incomplete. Hold Space to try again.`
- Copy button: `Copy` / `Copied ✓` / `Click to copy` / `Copy failed` (all unchanged).

**Accessibility:** no new interactive elements; Copy stays a real `<button>` toggled via `disabled`. Error banner keeps its current behaviour. Contrast of the dimmed state checked (AA).

## Tech plan
_Tech lead, 2026-09-27. **Verdict: does not fit level 0. Sent back to PM to split (Status → `specced`).** The plan below is written so that it carries over to the two split tickets unchanged; see "Size check" and "Proposed split"._

**Approach.** Change `POST /api/polish` in place rather than adding an endpoint. The spec rules out a parallel non-streaming mode, and a second endpoint would leave dead code behind. The server sends `"stream": true` and opens the upstream response with `client.send(build_request(...), stream=True)`, so it can still check the status *before* it commits to a 200. Non-200 → `aread()` → the existing `_upstream_error` 502. Upstream content-type not `text/event-stream` → JSON fallback: parse `choices[0].message.content` exactly as today, keeping the existing "Unexpected LLM Gateway response" 502. Otherwise it returns `StreamingResponse(media_type="text/plain; charset=utf-8")` from an async generator. The generator parses SSE the way AssemblyAI's own SDK does (`llm_gateway/v1/api.py::stream_completion`): skip lines not starting with `data: `, stop at `[DONE]`, `json.loads` the rest, and yield `choices[*].delta.content` when non-empty. Role-only and usage chunks carry no content. A `finally` closes both the response and the client. The browser keeps a plain `fetch` and reads `res.body.getReader()` with a streaming `TextDecoder`. On every chunk it re-renders the whole accumulated string with the existing `renderMarkdown`, which escapes first. I chose this over proxying raw SSE to the browser (which would need an SSE parser in JS; backend criterion 2 also requires plain text) and over `EventSource` (GET only, and it can't send the transcript body). No new dependencies: `StreamingResponse` ships with FastAPI, and `stream=True` and `aiter_lines` ship with httpx.

**Evidence the approach works (not a claim).** I built the whole change in a throwaway copy of the base branch (`<scratchpad>/plan`, diff saved at `<scratchpad>/t001-techlead-prototype.diff`). It is a reference only, not something to paste. Results:

**Risks.**
- **Gateway stream shape is unverified live.** The SDK itself says its SSE parsing is "verified against OpenAI-routed models only". The default `LLM_MODEL=gpt-5-mini` is OpenAI-routed. A non-OpenAI `LLM_MODEL` may produce no parseable `data:` lines, which gives an empty body and the `Polish failed.` path (visible, not silent). How we'll know: the owner's one live take (question already open).
- **Buffering.** If anything between the app and the browser buffers, the output arrives all at once. There's no middleware today; uvicorn flushes each yield. The e2e test fakes `fetch` in the page, so it can't catch this. Only the live take can.
- **Mid-stream upstream failure.** The generator raises after headers, uvicorn aborts the connection, and the browser reader rejects into the cut-off state. That is the intended behaviour, but `TestClient` re-raises server exceptions, so don't write a pytest for it without `raise_server_exceptions=False`.
- **httpx read timeout (30 s)** applies per read, not to the whole stream. That's fine for a stream; the same limit applies today.
- **Connect errors** from `client.send` are still an unhandled 500, as today. Out of scope; the client must still be closed.
- **e2e fidelity.** The polish response is faked in the page (an `add_init_script` override of `window.fetch`) because Playwright's `route.fulfill` can only deliver a whole body. The browser checks therefore cover the reader and UI states, not the server's framing. Backend acceptance tests cover the framing.
